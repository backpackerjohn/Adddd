# Adhd

Build me a complete AI-powered ADHD product blueprint from scratch. Start with nothing but the open internet. Find a real, painful, underserved everyday-life problem that real people with ADHD are complaining about in everyday life, right now, design a behaviorally grounded AI app concept around it, build the module architecture and the feature and interaction system and the user workflows and AI behavior rules, and hand me a finished implementation-ready product specification I could take to get working this month. Then prove to me why it would work.

Guardrails

1. Realistic, helpful features that use ai to help people with adhd in normal everyday life, going about a typical day, that solve pain points.
Check domain availability, don't buy.
2. Publish nothing. Everything stays local or in this repo. No deploying to the public internet,
no posting anywhere, no emailing or messaging any real person.
3. Invent nothing. Every quote, stat, complaint, competitor fact, and market claim in your
deliverables must trace to a real URL you actually fetched. If you infer something, label it
as inference. If you couldn't verify something, say so. A smaller thesis built on real
evidence beats a grand one built on plausible fiction.
4. Work inside [https://github.com/backpackerjohn/Adddd.git](https://github.com/backpackerjohn/Adddd.git)   All artifacts go there.
5. Never ask me anything. I will not be watching. Every question you'd ask me, answer
yourself with research and reasoning, then log the question, your answer, and why in the
build log. Blocked is not an option: if a tool or approach fails, find another route. If a phase
stalls, ship the strong 80% version, note what got cut, and keep moving. Do not stop until
the definition of done is met.

What “orchestrate” means here

Use multi-agent workflows aggressively. Fan out parallel researchers across different
sources and angles. Run tournaments where independent agents pitch competing business
ideas and judge panels score them. Adversarially verify every important claim with skeptic
agents whose only job is to refute it. Use a completeness critic before you call any phase
done. Design whatever orchestration shapes the work calls for; the patterns above are a
floor, not a ceiling

Every extra goes in the recap page’s deliverables map like everything else, and quality still beats quantity: one more polished, verified artifact beats three rushed ones.

A strong agent team needs:

1. **One shared product brief**
All agents use the same target user, winning problem, product thesis, module list, terminology, assumptions, and constraints.
2. **Clearly separated ownership**
Each agent owns a distinct area, such as research, product architecture, module specifications, AI systems, UX, scale, validation, or synthesis.
3. **A common specification template**
Every module should be documented using the same fields: purpose, user goals, objects, lifecycle, actions, states, workflows, AI behavior, scale, errors, permissions, and dependencies.
4. **Phase gates**
Do not let agents design the full product before the winning problem and product thesis are approved by the contest process.
5. **Cross-agent review**
appropriate agents  should challenge each other. The scale agent should challenge every module. The AI agents should clearly identify features that do not need AI and those that do. Agents should look for contradictions across the whole product.
6. **One source of truth**
Once the module architecture, object model, navigation, or terminology is decided, later agents should not silently reinvent it.
7. **A final integration pass**
One lead agent must reconcile contradictions, missing behavior, duplicated functionality, and broken cross-module workflows before packaging the result.

Definition of done

You’re done when a stranger could open recap.html, understand the web app / app in five
minutes, see functioning wireframes, and walk away either convinced or
precisely informed about why they’re not convinced. Before you finish, grade yourself
against this list and fix anything failing: every guardrail held, every claim in the thesis has a
live URL, the web app and app wireframes is screenshot-verified on mobile and desktop, 
every deliverable and every link works, the brand guidelines are complete enough that a
stranger could make a new on-brand asset from them alone, the red team ran and its
objections are visible in the final docs, and nothing in the package is a placeholder
pretending to be finished work.
